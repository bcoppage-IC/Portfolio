Balancing a Multiplayer Game with Simulation and OOAD

Concept and art by Myia Mack. Rules, economy, balance testing, and architecture by Ben Coppage. The game is revealed on November 27, so this page covers my methods and results, not the game itself.

  • 69%success rate in bot testing
  • 2.2point gap between player types (goal: 1 to 3)
  • ~25rule classes after the refactor
  • 8test suites run after every step

Problem

One of the three player types was winning more often than the others. The rules were also stuck inside one large file mixed with screen code, so they were hard to change or test.

What I did

  • Designed the rules and points economy.
  • Built a Python simulation that plays thousands of bot games.
  • Searched 1,800 level orders and 96 rule combinations to find the fairest setup.
  • Refactored the rules into about 25 classes using OOAD: one job per class, inheritance for player types, and private data.
  • Followed a 14-step refactor plan, running 8 test suites after every step.

How it was built

AI-assisted. I designed the rules, the class structure, and the test plan, and wrote the specs. AI coding tools (Claude Code, Antigravity) wrote the code from those specs. I checked every step with tests.

Results

  • About 69% success rate. In typical play, the three player types are within 2.2 points of each other, inside the 1 to 3 point goal.
  • One 844-line file became 19 rule files with no screen code mixed in.
  • The game can be saved, reloaded, and replayed exactly.

Known gaps

  • When players spend points strategically, the gap between types grows to about 9 points.
  • The screen code still assumes one local player. Multiplayer is the next phase.

Status

Under team review, not yet merged into the main game.
